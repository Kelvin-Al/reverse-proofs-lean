# Generating Lean theorems by reversing proof traces

We have been exploring a proof-first way to generate Lean examples. Start from an empty goal list. A model proposes a predecessor state and a tactic, and Lean checks that the tactic leads back to the current state. Repeat until the state can be written as a closed theorem statement, then replay the entire proof forward from that statement.

The latest experiment ran five traces in Lean 4.19.0. It checked 40 reverse transitions, then replayed all five complete proofs. The examples cover natural-number rewriting and induction, polymorphic lists, an existential witness, and a custom binary tree. In the tree example, the generator worked backward from a reflexive equality to recover two induction-hypothesis rewrites, reconstructed the leaf case, and merged the goals into an induction on the tree. Lean also rejected a control that kept the variable names and goal count but changed an induction hypothesis's type.

The earlier propositional experiments include hand-written rule and direct-generation comparisons. Both alternatives could complete the small tasks. We are sharing reverse generation as an additional way to construct and inspect theorem–proof pairs. The LLM traces in this prototype were generated by prompting a dialogue model and are included as replayable data.

We would be interested in discussion on two questions.

1. What is the right boundary between a portable serialized proof state and Lean-specific state, especially for dependent contexts and shared metavariables?
2. Which further examples would best illustrate what can be expressed by local reverse transitions, particularly across induction branches?

The repository includes the Lean verifier, candidate states, full proofs, negative controls, and Python replay scripts. Start with the mathematical examples in the README.
