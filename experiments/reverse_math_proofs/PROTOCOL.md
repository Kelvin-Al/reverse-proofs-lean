# 从空状态逆向生成 Lean 数学证明

## 任务

本轮是五条可行性轨迹。每条只指定题材或推理机制，自空目标列表 `[]` 开始，无预先给定的待证命题或证明种子。本对话模型分轮提出候选前驱状态及一个能把它变回当前状态的 tactic，每条活跃轨迹每轮一个候选。每轮在 Lean 检查后才继续。局部上下文为空、只剩一个目标时停止，再从生成的命题完整重放。

背景包含 Lean 自带的自然数和列表，以及一份预先定义的二叉树类型及其 `mirror`、`nodes` 函数。背景定义是允许使用的词汇。实验的最终定理和证明由轨迹产生。这些都是小型数学例子，部分结论是熟知的性质。

## 验证器

- 状态保存有序目标，每个目标带一个有序的局部上下文。用 `∀` 绑定重建上下文，使后面的声明可引用前面引入的类型、对象或归纳假设。带 `h` 前缀的绑定名留给状态中的局部变量，命题自己的量词使用其他名字。
- 对每条边，Lean 从前驱状态创建实际目标，执行指定 tactic，比较后继的目标数、顺序、局部名字和整个带上下文的命题类型。命题类型用 Lean 的定义等价检查。`induct_nat`、`induct_list`、`induct_tree` 是普通 Lean `induction` 的薄封装，用来统一分支变量命名和顺序。它们只执行正向 tactic。
- 对每条完整轨迹，从最终定理重新执行所有 tactic，在每个检查点重新验证状态，并要求最终定理不依赖公理。归纳负对照保留目标数与局部变量名，只替换归纳假设的类型。
- 开发时修正了一处输入词法限制，接受 Lean 合法的 Unicode 变量名。修正后重放了相同的冻结候选。

## 复现

安装 Python 3.10+ 和 Lean 4.19.0。通过 elan 安装 Lean 后，在解压出的目录执行：

```sh
python3 experiment.py
```

也可加 `--lean /absolute/path/to/lean`。无需 mathlib。`llm_rounds/` 保留每轮冻结的候选。默认运行从头检查全部边和完整证明，输出 `results.json`，其中有实际提交给 Lean 的源码及诊断。`--gate-cache` 用于交互式增量检查，不是复现依赖。`Generated.lean` 便于直接阅读生成的最终定理和证明。

本轮是用本对话模型进行的提示式生成，未训练逆向模型。五条轨迹只支持在这个 Lean 片段内的可行性结论。

## 结果

| 轨迹 | 最终命题 | 验证的逆向边 |
|---|---|---:|
| 自然数重写 | `(a + b) + c = (a + c) + b` | 7 |
| 自然数归纳 | `Nat.succ a + b = Nat.succ (a + b)` | 7 |
| 多态列表归纳 | `List.map f (xs ++ ys) = List.map f xs ++ List.map f ys` | 10 |
| 列表存在性 | 存在长度比 `xs` 大 1 且尾部为 `xs` 的列表 | 7 |
| 自定义二叉树归纳 | 镜像保持 `nodes` 定义的节点数 | 9 |

40 条逆向边全部通过，五条最终证明全部重放成功且无公理依赖。替换了归纳假设类型的负对照被拒绝。

在二叉树轨迹里，从分支末端的自反等式出发，生成器先逆转加法交换，再依次逆转两次归纳假设重写。随后补出叶节点目标，把叶节点与分支目标合并为同一个关于整棵树的归纳目标，最后抽象出类型和树变量。
