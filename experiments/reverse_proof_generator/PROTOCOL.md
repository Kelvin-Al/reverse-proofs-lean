# 从空目标生成命题与证明

## 复现

使用 Python 3.10+ 和 Lean 4.19.0。通过 elan 安装 Lean 后，在解压目录中运行：

```sh
python3 experiment.py
```

也可通过 `--lean /absolute/path/to/lean` 指定 Lean。只使用 Lean 自带的库。脚本写出 `results.json`，其中保留每条候选、实际提交给 Lean 的源码与诊断。复跑使用冻结的候选。用 `--gate` 可以检查当前 `llm_rounds/` 中各批次之后的状态。

## 设置

三个方法各生成 8 条轨迹或完整证明。每条最多 8 条 tactic 指令，允许 `intro`、`exact`（含合取投影）、`apply`、`constructor`、`left`、`right` 和 `cases`。`cases ... <;> rename_i ...` 作为一条指令计数。命题使用 `P Q R S : Prop` 与 `→ ∧ ∨`，单个公式最多 12 个联结词。

- **LLM 逆向。** 本对话模型分轮给出前驱目标列表和 tactic。每条轨迹从 `[]` 开始，输入中没有目标命题或种子证明。每个仍在运行的轨迹每轮一个候选，失败则停止。Lean 验证该 tactic 能从前驱到达上一轮状态后，才继续扩展。找到单目标、无局部证明假设的状态时停止。
- **规则逆向。** 同样从 `[]` 开始，用八套固定的规则组合安排产生轨迹。规则包括逆向添加由局部假设解出的目标、合并合取、合并分情况、增加析取和抽象局部假设。使用与 LLM 逆向相同的 Lean 检查。
- **LLM 直接。** 本对话模型一次性给出 8 个命题及其正序 tactic 序列，输入中同样没有指定目标或种子。直接组收到的是同一语法与长度约束。两组 LLM 候选均来自本对话，并非独立模型调用。

## 验证

每条逆向边由 Lean 从候选前驱构造实际目标，执行 tactic 后检查目标数、顺序、局部假设和类型。达到起始状态后，再从最终命题正向重放整条轨迹，同时逐步检查实际状态，最后检查定理没有公理依赖。直接生成组检查完整重放及公理依赖。验证器包含一个正对照和一个交换两个分支顺序的负对照。

联结词结构保留公式树的联结词、顺序及分组，忽略原子的名称和相等关系。原子重命名去重保留原子间的相等关系。两者均为语法指标。

本轮匹配了起始轨迹数和 tactic 步数上限，没有匹配模型 token、生成时间或 Lean 调用成本。LLM 逆向由本对话模型提示式运行。实验没有训练逆向转移模型、估计独立样本的成功率，或使用 jixia/mathlib 轨迹。

## 本轮结果

| 指标 | LLM 逆向 | 规则逆向 | LLM 直接 |
|---|---:|---:|---:|
| 完整证明通过 Lean | 8/8 | 8/8 | 8/8 |
| 按原子重命名去重后的命题数 | 8 | 8 | 8 |
| 不同联结词结构数 | 8 | 8 | 8 |
| 包含析取分情况的证明数 | 2 | 2 | 2 |
| tactic 指令数范围 | 3–7 | 2–7 | 2–8 |
| 通过的逆向转移 | 43/43 | 37/37 | 不适用 |

LLM 逆向分别与另外两组共享 1 种联结词结构，规则逆向与 LLM 直接共享 2 种。三组样本小，且生成预算只匹配了尝试条数与步数上限。这些计数说明了生成器能产出哪些结果，以及三组在本轮的覆盖差别。

逆向生成的一条轨迹产生了 `(P → Q) → (P ∨ Q) → Q`。逆向构造先选择由局部假设直接解出的末端，再构造两个分支。一个分支用 `P → Q` 将 `P` 变成 `Q`，另一个分支已经有 `Q`。通过逆转 `cases` 将两个分支合为带有 `P ∨ Q` 假设的状态，随后两次逆转 `intro` 得到定理。完整正向证明如下：

```lean
theorem generated (P Q : Prop) : (P → Q) → (P ∨ Q) → Q := by
  intro h0
  intro h2
  cases h2 <;> rename_i h1
  apply h0
  exact h1
  exact h1
```
